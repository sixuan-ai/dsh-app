## 方法与画质约束

1. SHA-256 确认 `waiting` 与 `working_search` 原文件完全相同；两个状态名继续保留，共享 `waiting.webp`，节省约 4.06 MB。
2. 使用原始解码帧重新编码为 animated WebP；保留每个原动作完整的逻辑时间轴、画布大小及循环设置。
3. 原素材背景大量像素透明度为 1/255。仅将透明度 ≤1/255 的像素归零并清理其隐藏 RGB；所有更高透明度值保留，输出透明度逐像素最大误差限制为 1/255。
4. 编码器可将重复画面合并为较长停留时间。15 段独立动画共存储 3,084 个编码帧，逻辑时间轴仍含全部 3,444 个 42 ms 时隙（包括两个共享动作）。没有截断动作、缩短时长或统一降低采样帧率。
5. 压缩档位从 50 开始，对全部逻辑帧逐帧验证，不满足门槛就升到 68、85；仍不满足或输出变大则回退原文件。本次所有独立动作最终选择 68。

SSIM 在实际主角展示尺寸 230 × 192、深色/浅色/青柠三种背景上逐帧计算，只在参考图可见区域统计，避免透明空白抬高指标。所有逻辑帧最低 SSIM 为 **0.985369**，按逻辑帧加权平均约 **0.989876**。这一结果衡量实际展示尺寸的相似度；采用的是用户同意的有损编码。

原始静帧 `poster.webp` 与许可证逐字节保留。压缩后的动作仍全部内置在安装包，不依赖首次下载、资源包服务器、WebView 或新增视频播放插件。

## 工具和复现

- `tool/import_dafeiyu.py` 仍可从固定上游提交复现原始素材容器。
- `tool/optimize_dafeiyu.py` 从原始素材目录生成新的临时目录，边编码边验证，不会原地覆盖输入。输出必须为新目录或空目录。
- 构建机需要 Pillow 与 numpy；本次编码环境为 Pillow 12.1.1 / libwebp 1.5.0。客户端无新增依赖。
- `animation-optimization.json` 保存全部动作、原始与优化后哈希、各逻辑时间轴、体积及画质指标；同样的数据随应用 `provenance.json` 提供。

```bash
python3 tool/import_dafeiyu.py \
  --source /path/to/pinned/dsh-dafeiyu \
  --output build/dafeiyu-original
python3 tool/optimize_dafeiyu.py \
  --input build/dafeiyu-original \
  --output build/dafeiyu-optimized-new \
  --workers 4
```

验证完成后同步生成目录至 `assets/pet/dafeiyu/`，并依据 `clips.*.asset` 保留唯一动画文件。共享动作不能再次以独立副本打包。`dafeiyuAnimationAsset` 与元数据的文件对应关系由测试校验。

[WebP 官方编码选项](https://developers.google.com/speed/webp/docs/img2webp)提供最小尺寸、压缩质量与关键帧策略的说明。
